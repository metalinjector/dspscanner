## Замер

Один синтетический PDF: 12 растровых страниц A4, по 25 строк русского текста,
300 вхождений слова «время». Linux, 9 доступных логических CPU,
Tesseract 5.3.4, одинаковая русская модель tessdata_fast для обеих версий.
Модели взяты из коммита `87416418657359cb625c412a48b6e1d6d41c29bd`.

| Вариант | Время, с | Совпадения | Ошибки |
|---|---:|---:|---:|
| Исходный коммит, холодный запуск | 6,841 | 300 | 0 |
| Исправления, adaptive, холодный запуск | 3,146 | 300 | 0 |
| Исправления, повтор в том же процессе | 0,056 | 300 | 0 |

Холодный запуск на этом документе быстрее примерно в 2,17 раза.
Это один последовательный замер на синтетическом документе, а не статистическая
оценка или гарантия ускорения на других PDF. Равенство числа совпадений не измеряет
точность всего распознанного текста. Повторный запуск использует кэш в памяти;
после перезапуска приложения кэш пуст.

Хэши моделей SHA-256:

```text
rus e16e5e036cce1d9ec2b00063cf8b54472625b9e14d893a169e2b0dedeb4df225
eng 7d4322bd2a7749724879683fc3912cb542f19906c83bcc1a52132556427170b2
```

Для собственного корпуса:

```bash
python -m tools.benchmark_pdf_ocr document.pdf --term время --repeat 2
```

Сравнивайте не только время, но и найденные слова и предупреждения. Для оценки
точности нужен размеченный корпус реальных документов с поворотами, шумом,
мелким текстом, таблицами и несколькими языками.

## Основания выбора параметров

- [Tesseract: улучшение качества](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html):
  разрешение, сегментация и качество входного изображения.
- [Tesseract: FAQ](https://tesseract-ocr.github.io/tessdoc/FAQ.html):
  ограничение OpenMP при параллельной обработке изображений.
- [Модели Tesseract](https://tesseract-ocr.github.io/tessdoc/Data-Files.html):
  различия fast, tessdata и best; совместимость с OEM.
- [PyMuPDF: multiprocessing](https://pymupdf.readthedocs.io/en/latest/recipes-multiprocessing.html):
  PyMuPDF не поддерживает многопоточное использование документа.

200 DPI и пороги повторного распознавания — эвристики проекта, а не универсальные
оптимальные параметры Tesseract. Режим thorough начинает с 300 DPI; большие
страницы ограничиваются по числу пикселей. Итоговую настройку следует выбирать
по качеству и времени на собственном корпусе.
