# DSP Scanner (Python-версия)

Полный перенос PowerShell-скрипта **`dspscanner.ps1`** на Python с сохранением
100% исходного функционала, модульной архитектурой и современным
графическим интерфейсом на **PySide6 (Qt 6)**.

## Что делает программа

1. Рекурсивно ищет файлы `.docx`, `.doc`, `.txt`, `.pdf` в указанных папках,
   пропуская системные/скрытые каталоги, временные файлы (`~`, `~$`) и
   дубликаты путей.
2. Извлекает текст из каждого файла:
   - **DOCX** — быстрый прямой разбор безопасного ZIP/XML-контейнера
     (текст, таблицы, колонтитулы, сноски и комментарии) с `python-docx` как
     совместимым резервным способом;
   - **DOC** — автоматический каскад: быстрая эвристика OLE2 → LibreOffice
     headless → MS Word COM (только Windows); отдельно
     распознаются файлы, реально являющиеся RTF/HTML/Word 2003 XML/DOCX под
     расширением `.doc`;
   - **TXT** — определение BOM/кодировки (UTF-8/UTF-16/CP1251, авто-детект
     через `charset-normalizer`);
   - **PDF** — **новый функционал** (в оригинале отсутствовал): извлечение
     текста через `PyMuPDF`, с опциональным прямым запуском Tesseract для
     сканов без текстового слоя; Python-обёртки OCR не требуются.
3. Использует два независимых списка терминов: один для поиска в содержимом
   документов, второй — только в названиях файлов. Пустое поле полностью
   отключает соответствующий вид поиска. Совпадения по имени помечаются в
   колонке «Контекст» префиксом `[Имя файла]` и находятся без открытия файла.
   По умолчанию разрешены совпадения внутри слова: `пилот` находит
   `беспилотник`; режим «Целые слова» отключает такое поведение.
4. Показывает совпадения в таблице сразу после обработки каждого файла, не
   дожидаясь завершения всего сканирования; параллельно обновляет вкладку
   «Файлы», статистику и журнал ошибок.
5. Экспортирует отчёт в **Excel** (три листа: результаты, статистика,
   ошибки), **CSV** или **Markdown**; при необходимости автоматически
   отправляет отчёт по SMTP.
6. На вкладке «Файлы» показывает уникальные полные пути найденных файлов с
   чекбоксами, копирует только отмеченные файлы и позволяет напрямую выполнить
   безопасное удаление или перемещение.
7. При безопасном перемещении сначала создаёт и проверяет копию по SHA-256,
   затем многопроходно перезаписывает и удаляет оригинал с прежнего места.

## Изменения версии 2.9.9

- OCR-конвейер теперь запускает Tesseract сразу после рендеринга каждой
  страницы, не дожидаясь подготовки всего чанка. Это перекрывает рендеринг
  следующей страницы с распознаванием предыдущей, сохраняя прежний лимит
  не более 4 PNG в работе.
- UTF-16LE-эвристика legacy DOC переведена на `memoryview` со stride. Выход
  побитово совместим с прежним алгоритмом, а контрольный проход по 10,4 МБ
  текста ускорился примерно с 0,94 до 0,60 с.
- CLI корректно обрабатывает `KeyboardInterrupt` как отмену с кодом 130, а не
  как внутреннюю ошибку. `SystemExit` больше не перехватывается общим блоком.
- Рекомендованное снижение порога Aho–Corasick до 8 не применено: замеры
  показали, что для 8–16 отсутствующих терминов автомат заметно медленнее
  regex-ветки. Существующий безопасный порог 32 сохранён.
- Постоянный пул рискованных процессов, общий профиль LibreOffice и другие
  крупные изменения не применялись без отдельного нагрузочного стенда.

## Изменения версии 2.9.8

- Добавлена зависимая от OCR настройка **«Искать только на первых N страницах
  PDF»**. По умолчанию ограничение выключено, рекомендуемое стартовое значение
  — 10 страниц. Настройка сохраняется в переносимый JSON и доступна в CLI через
  `--pdf-first-pages N`; `0` означает все страницы.
- Обход каталогов и чтение документов теперь работают конвейером через
  ограниченную очередь: обработка начинается до завершения полного обхода
  большого дерева, что сокращает время до первого результата и удерживает
  потребление памяти.
- Режим DOC **«Авто»** сначала использует быструю эвристику и запускает
  LibreOffice/MS Word только при неудаче, уменьшая число тяжёлых внешних запусков.
- Для DOCX прямой XML-парсер стал основным. На контрольной таблице 500×5 он был
  примерно в 6–7 раз быстрее `python-docx`, при совпадающем извлечённом тексте.
- Архитектурно рискованный переход на постоянный пул процессов пока не выполнен:
  существующая изоляция, таймауты и гарантированное завершение дерева внешних
  процессов сохранены без изменений.

## Аудит и оптимизация (v2.4.0)

- **Реальные жёсткие таймауты для PDF/DOC и крупных DOCX.** Потенциально
  зависающие парсеры запускаются в изолированных процессах. При таймауте или
  отмене завершается вся группа процессов, включая LibreOffice/Tesseract.
- **Быстрая отмена и ограниченная очередь.** В памяти одновременно находится
  не более `2 × число потоков` задач, поэтому большие наборы файлов не создают
  сотни тысяч `Future`, а отменённые задачи не продолжают запускать ридеры.
- **Ускоренный поиск по большому списку обычных слов.** Для 32 и более
  литеральных терминов используется однопроходный алгоритм Aho–Corasick;
  wildcard-фразы и сложные случаи сохраняют прежнюю regex-семантику.
- **Защита DOCX от ZIP/XML-бомб** по числу элементов, распакованному объёму,
  размеру XML-частей и коэффициенту сжатия.
- **Ограничение памяти OCR.** DPI автоматически снижается для страниц
  необычно большого формата, чтобы растр одной страницы не исчерпал память.
- **Безопаснее экспорт и файловые операции.** Нейтрализованы формулы Excel/CSV,
  удалены недопустимые XML-символы, запись отчётов и настроек атомарная,
  копирование не перезаписывает существующие файлы, разрушительные операции
  отклоняют символьные и жёсткие ссылки и повторно проверяют идентичность файла.
- **Исправлен запуск GUI:** устранена ошибка инициализации кнопки копирования;
  добавлен автоматический offscreen-smoke-тест главного окна.


## Редизайн интерфейса (v2.3)

- **Устранено наложение элементов панели настроек.** Прежняя компоновка
  (GroupBox + QGridLayout) при нехватке высоты окна «складывалась»: Qt
  накладывал строки сетки друг на друга (комбобокс «Метод .doc» наезжал на
  чекбокс «Целые слова», спинбоксы слипались). Панель переработана: плоские
  секции с заголовками и вогнутыми (гравированными) линиями-разделителями
  вместо рамок, обёртка в QScrollArea — при любой высоте окна содержимое
  сохраняет размеры, при нехватке места появляется прокрутка, а не наложение.
- **Закреплённая панель действий**: кнопки «Начать поиск» и «Проверить 1 файл»
  вынесены из прокручиваемой области и видны всегда.
- **Современные чекбоксы** со скруглённым индикатором и акцентной галочкой,
  акцентная подсветка поля в фокусе, компактные кнопки управления путями.
- При штатном размере окна (1400×880) вся панель помещается без прокрутки —
  проверено автотестом геометрии (попарные пересечения виджетов, видимость
  главной кнопки, пиксельная проверка разделителей) на трёх размерах окна.

## Оптимизации производительности и надёжности (v2.2)

- **Рабочий пер-файловый таймаут и отзывчивая отмена.** Прежняя схема
  `as_completed + future.result(timeout=...)` не срабатывала никогда (метод
  отдаёт только уже завершённые задачи): один повреждённый PDF, повесивший
  PyMuPDF, блокировал весь скан, а кнопка «Стоп» переставала действовать.
  Теперь пул опрашивается через `concurrent.futures.wait` c шагом 0.5 с:
  зависший файл по истечении таймаута помечается ошибкой и пропускается,
  скан продолжается, «Стоп» срабатывает максимум за полсекунды.
- **Параллельный OCR страниц.** Страницы одного PDF распознаются параллельно
  (tesseract — отдельный процесс, GIL не мешает); суммарное число процессов
  tesseract ограничено числом ядер CPU глобальным семафором, внутренние
  OMP-потоки tesseract ограничиваются при страничном параллелизме. На
  одноядерных машинах поведение остаётся последовательным (без регрессии).
  Растеризация страниц — чанками по 4 (объект Document PyMuPDF не
  потокобезопасен + ограничение пиковой памяти, приём из MinerU).
- **Язык OCR определяется один раз на процесс** по списку установленных
  traineddata, вместо каскада попыток rus+eng→rus→eng на каждой странице
  каждого файла; устранён тройной прогон OCR по действительно пустым страницам.
- **Детект «битого» текстового слоя PDF** (идея из MinerU): страницы, где
  вместо букв — маркеры `(cid:NN)` или символы-заменители, дополнительно
  отправляются в OCR; исходный текст при этом сохраняется.
- **Кэш настроек приложения**: `load_settings()` с автодетектом внешних
  программ ранее выполнялся на каждый .pdf/.doc файл из всех потоков; теперь
  результат кэшируется и сбрасывается при сохранении из диалога «Параметры».

## Что улучшено относительно оригинала

- **Параллельная обработка файлов** (`ThreadPoolExecutor`) вместо
  последовательной обработки одного файла за раз — на больших деревьях
  каталогов ускорение в разы.
- **PDF читается по-настоящему** (в ps1-версии эта функция была лишь
  заглушкой, всегда возвращавшей пустой результат).
- DOC читается через LibreOffice/MS Word, когда это возможно — значительно
  точнее, чем побайтовый эвристический разбор, который используется только
  как последний резервный вариант.
- Определение кодировки TXT через `charset-normalizer` вместо жёстко
  заданной CP1251.
- Безопасное удаление перезаписывает файл случайными данными (а не только
  нулями).
- Современный, отзывчивый GUI на Qt6 вместо консольного меню; сканирование
  выполняется в фоновом потоке, прогресс и журнал обновляются в реальном
  времени, есть отмена операции.
- Добавлен **таймаут на один файл** — защита от зависания на повреждённых
  или очень больших файлах (в оригинале скрипт мог "застрять" навсегда).
- MS Word COM инициализируется один раз на поток обработки, а не на каждый
  файл — устраняет накладные расходы.

## Архитектура интерфейса (v2)

Главное окно разделено на три зоны, что устраняет проблему «хаотичного
изменения границ» и «невидимого прогресса» из первой версии:

```
┌──────────────────────────────────────────────────────────────┐
│  Меню: Файл · Настройки · Справка                              │
├──────────────────────────────────────────────────────────────┤
│  [████████░░░░░░]  123/456 — file.docx           [■ Стоп]    │  ← Прогресс-бар
├────────────────────┬─────────────────────────────────────────┤
│  Левая панель      │  Правая панель (вкладки)                 │
│  ┌─ Пути ────┐    │  [Результаты] [Файлы] [Журнал]            │
│  │ список   │    │                                            │
│  └──────────┘    │  Таблица найденных совпадений с           │
│  ┌─ Слова ───┐   │  подсветкой найденного слова, фильтр,      │
│  │ textarea │   │  экспорт в Excel/CSV/Markdown              │
│  └──────────┘    │                                            │
│  ┌─ Параметры┐   │                                            │
│  │ типы,    │   │                                            │
│  │ метод .doc│   │                                            │
│  └──────────┘    │                                            │
│  [▶ Начать]     │                                            │
│  ┌─ Статистика┐  │                                            │
│  │ 8 карточек│   │                                            │
│  └──────────┘    │                                            │
├────────────────────┴─────────────────────────────────────────┤
│  Статус-бар: Готово / Сканирование...                        │
└──────────────────────────────────────────────────────────────┘
```

Ключевые решения:
- **Прогресс-бар всегда сверху**, виден на любой вкладке — пользователь
  всегда видит, на каком этапе находится сканирование.
- **Автопереключение вкладок отключено** — пользователь сам выбирает,
  какую вкладку смотреть (Результаты / Файлы / Журнал).
- **Stat cards имеют фиксированные размеры** (через QSS) — цифры разной
  длины больше не «прыгают» при обновлении.
- **Таблица результатов**: колонка «Контекст» в режиме `Interactive` (без
  `Stretch`) — устраняет перерасчёт геометрии при добавлении строк. Ширина
  подгоняется под самую длинную реальную строку контекста и ограничена
  снизу и сверху, поэтому справа не остаётся пустого места, а очень длинный
  контекст не выталкивает остальные столбцы за экран. Если ширину изменить
  мышью, автоподгонка отключается. Подсветка найденного слова через делегат.
- **Кнопка «Стоп»** в строке прогресс-бара, всегда доступна во время
  сканирования.

### Файлы с одинаковыми именами

Одно и то же имя нередко встречается в разных каталогах — копия отчёта в
архиве, дубликат в папке отдела. В таблице такие строки выглядели одинаково,
а различить их можно было только по столбцу «Путь», который находится
крайним справа и обычно за пределами экрана.

Теперь к имени добавляется минимальный отличающий хвост родительского пути,
и только для имён, реально встречающихся в нескольких каталогах:

```
123456testbesp.pdf › Отдел кадров
123456testbesp.pdf › Архив/2024
beso.pdf
```

Если различаются уже сами родительские папки, показывается одна; если
совпадают и они — две и так далее. Имя стоит первым, поэтому сортировка по
столбцу «Файл» остаётся сортировкой по имени, а копии оказываются рядом.
Столбец «Путь» не меняется: по нему по-прежнему открывается файл.

### Точка отсчёта прогресса

Флажок **«Сначала подсчитать все файлы»** включён по умолчанию. Перед чтением
документов выполняется быстрый обход каталогов, и общее число файлов известно
с первого же обработанного документа — полоса заполняется равномерно от 0 до
100%. Пока идёт подсчёт, полоса находится в неопределённом режиме, а над ней
отображается «Предварительный подсчёт файлов: N», так что задержка перед
стартом объяснена, а не выглядит зависанием.

Документы при подсчёте не открываются: обход опирается на `os.scandir` и
занимает доли секунды даже на тысячах файлов. Фильтры совпадают с основным
проходом, поэтому итог равен числу файлов, которые действительно будут
прочитаны.

Без этой настройки поиск файлов и их обработка идут одновременно: обработка
стартует сразу, но знаменатель прогресса растёт по мере обхода, из-за чего
доля выполнения регулярно откатывается назад (например, 67% → 58%). Отключать
подсчёт имеет смысл на очень медленных сетевых дисках, где сам обход каталогов
занимает заметное время и важнее начать читать документы немедленно. В CLI —
ключи `--precount` и `--no-precount`.

## Установка

Нужен Python 3.10 или новее.

```bash
git clone https://github.com/metalinjector/dspscanner.git
cd dspscanner
python -m venv .venv
# Windows: .venv\Scripts\activate       Linux/Mac: source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### Проверка установки

Сразу после установки стоит убедиться, что на этой машине собралось всё
необходимое — быстрее, чем обнаруживать нехватку зависимости посреди
сканирования:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest
```

Набор проходит без LibreOffice, Tesseract, MS Word, SMTP-сервера и
графической сессии: Qt поднимается в offscreen-режиме, а проверки, которые
на этой платформе невозможны (например, символьные ссылки в Windows без
Developer Mode), помечаются как пропущенные, а не как ошибки. Если тесты
зелёные — рабочими являются и GUI-, и CLI-режим.

Дополнительно (по желанию, необязательно для базовой работы):

- **LibreOffice** — для максимально точного чтения `.doc` без Windows/MS Word.
- **Tesseract OCR** — для распознавания сканированных PDF без текстового слоя.

Пути к LibreOffice и Tesseract можно задать в диалоге **«Настройки → Параметры»**.
Для переносимого OCR поместите файлы Tesseract в каталог `Tesseract-OCR`
рядом с `main.py` или исполняемым файлом. Кнопка «Определить автоматически»
сначала проверяет эту папку, затем PATH и стандартные каталоги установки.

## Запуск

Графический режим:

```bash
python main.py
```

Командный режим без GUI:

```bash
python main.py --cli --help
python main.py --cli --config DSPScanner_Config/search_settings.json --send-email
```

Полное описание находится в `CLI_COMMANDS.txt`. Для headless-сервера можно
установить только `requirements_cli.txt` — он не тянет PySide6, и GUI в таком
окружении недоступен.

Быстрая проверка, что всё работает, на любой машине:

```bash
python main.py --cli --no-config --path <папка> --content-terms "договор" --types txt
```

На Windows приложение использует собственный AppUserModelID, поэтому получает
отдельную иконку и группу на панели задач.

## Горячие клавиши

- `Ctrl+S` — сохранить конфигурацию поиска (пути, слова, опции) в JSON.
- `Ctrl+O` — загрузить конфигурацию поиска.
- `Ctrl+Q` — выход.

## О тестировании

Проверки лежат в каталоге `tests/` и запускаются на любой машине командой
`python -m pytest` после установки `requirements-dev.txt`. Внешние программы,
сеть и графическая сессия не нужны.

Что покрыто:

- **поисковый движок** — границы целых слов (включая термины с пунктуацией
  вида `C++`, `№ 42`), wildcard, свёртка `ё/е`, регистр, лимит совпадений и
  совпадение результатов regex-ветки и Aho-Corasick-ветки;
- **обход дерева** — границы сканирования (символьные ссылки не выводят за
  пределы выбранных каталогов), дедупликация, временные файлы, лимиты размера,
  служебные и скрытые каталоги;
- **читатели** — DOCX с обычным текстом и с импортированным altChunk-разделом,
  повреждённый контейнер, отбой ZIP-бомбы, кодировки TXT (BOM, UTF-16, CP1251);
- **экспорт** — создание xlsx/csv/md, состав вложений, нейтрализация формул
  Excel и HTML в данных из чужих документов, отсутствие временных файлов;
- **сквозной прогон** — оркестратор сканирования и запуск CLI отдельным
  процессом с проверкой отчёта и summary JSON; отмена сканирования;
- **почта** — блокировка подстановки заголовков SMTP, валидация адресов,
  пароль из окружения и запрет сохранения пароля без явного разрешения;
- **GUI** — offscreen-сборка главного окна, модель результатов, экранирование
  HTML в подсказках, диагностическое чтение файла в отдельном потоке.

Дополнительно:

- `python -m ruff check .` — без замечаний (конфигурация в `pyproject.toml`);
- `python -m compileall app main.py` — без синтаксических ошибок.

Тесты про символьные ссылки автоматически пропускаются в Windows без прав на
их создание, а GUI-тесты — если PySide6 или системные библиотеки Qt
отсутствуют. Пропуск означает «на этой платформе проверка неприменима», а не
скрытую ошибку.

Перед боевым использованием OCR рекомендуется проверить на нескольких
реальных сканах с установленными языковыми пакетами Tesseract. Журнал ошибок
доступен во вкладке «Журнал» и в `~/DSPScanner/logs/search_errors.log`.
